### 001-pruning — Does aggressive hypothesis pruning improve predictions?
Status: closed — no integration.
Baseline: `be25423`; core hash `0633d22fb7d1c9d4699fecf4ff851b59cb97c638bcbd6be17db0176865331146`; experiment implementation `f7f4b9b`; 2026-09-18.
Comparison: 400 public training tasks only; 55 have a depth-2 fitting program, 32/55 already have unanimous defined test answers. Frozen uniform syntax class, no repair/fallback; no symmetry vs fixed/random/marginal-pruning policies; seeds 0–4; 12 workers; 500,000 charged checks per task/policy; closure caps 300 and 1000.
Result: at **both caps**, no symmetry and fixed order solve 53/400; marginal pruning 51/400 in every seed; random order mean 51/400 (range 50–52). Fixed/pruning reduce mean program entropy by 0.41/0.57 bits and mean answer entropy from 0.68 to ~0.02 bits, but leave 2/4 unanimous wrong tasks. Pruning loses all initially correct programs on 3 tasks versus fixed's 1. No budget exhaustion. At cap 1000 every pruning trial closure completes, so its losses persist without closure sampling. Full five-seed rounds take 10.71s / 13.86s including shared preparation.
Decision: reject maximum pruning as a standalone selection objective in this setup. It increases certainty while discarding correct explanations. This does not reject entropy as a diagnostic, other priors, or other selection objectives. No evaluation-set run or stable-core change. This compares selection/stopping policies within a common functionality prefilter, not the complete stable solver; it is exploratory evidence on the same 400 tasks across seeds.
Counterexamples: `1cf80156`: fixed 100→58 programs, correct `cropBBox`; pruning 100→6, unanimously wrong `cropBBox ; dedupCols`. `1f85a75f`: fixed 70→25, correct `cropLargest`; pruning 70→2, unanimously wrong `cropLargest ; recolour 2 0`.
Code/evidence: completed code deleted; runnable implementation is preserved at `f7f4b9b`. Retained [protocol](evidence/001-pruning/protocol.md), direct [cap-300 report](evidence/001-pruning/cap-300/report.md) and [cap-1000 report](evidence/001-pruning/cap-1000/report.md), with original manifests and logs. Depth sensitivity is examined in 002-depth.

### 002-depth — Does depth 3 create useful headroom for program entropy?
Status: closed — depth sensitivity measured; no policy integration.
Baseline: `3b8cf66`; implementation `2114781`; measured core hash `e76a7031af456aeba4348a32b08e32017f44641eb17256e1b01e09a5985a7f5c`; 2026-09-18. The only core change omits the unused final enumeration frontier, preserving programs and ordering; all 11 core tests, experiment checks, and solver regressions passed.
Comparison: exhaustive depth 2 vs 3; all 23 depth-2 ambiguous public training tasks plus 24 deterministic hash-selected unfitted tasks. Same primitives and shortest-program selection; no symmetry/fallback. Twelve workers; 12-task pilot (29.95s, 262 MiB peak RSS) followed by 47-task run (52.04s, 474 MiB). Full depth-2 census reproduced 55 fitting / 32 determined tasks. No evaluation tasks.
Result: on ambiguous tasks, mean fitting programs **60.61→3294.35**, mean program entropy **5.647→11.087 bits**, mean answer entropy **1.615→2.366 bits**. New joint test predictions on 17/23 tasks; six gain syntax without new joint answers. Shortest selection stays **22/23**, oracle stays **23/23**: only one task of improvement headroom. **0/24** previously unfitted tasks gain a depth-3 fit. Cohort-wide task exact match stays 22/47, grid exact match 23/51; these selected-cohort rates are not corpus estimates. All depth-2 pools are preserved exactly inside depth 3; pilot/full overlapping pools agree byte-for-byte.
Decision: depth 3 is affordable here and supplies a richer uncertainty diagnostic, but gives no additional accuracy headroom in this cohort. This does not establish the depth-3 performance of the pruning policy (not rerun), nor rule out gains among other unfitted tasks. Expressivity is the next priority, explored through objects in 003 rather than the deferred prior-only comparison. No entropy policy enters core.
Code/evidence: retained direct [selected report](evidence/002-depth/selected/report.md), [pilot report](evidence/002-depth/pilot/report.md), manifests, logs, and selection. ### 003-objects — Are object interpretations expressively and predictively useful?
Status: candidate — object language retained; no core integration.
Baseline: `3c4b94a`; unchanged core hash `e76a7031af456aeba4348a32b08e32017f44641eb17256e1b01e09a5985a7f5c`; grammar/initial run `dc8ada2`, refined report `c8b4552`; 2026-09-18.
Comparison: finite segment/select/act/render AST with eight competing object interpretations versus exhaustive core depth 2, on 400 public training tasks. Reserve the last training pair to compare predictive probability, entropy, Brier loss and accuracy; its output never enters discovery search/palette. A fixed gate chooses the family with greater reserved-answer probability, then refits all pairs. Pilot 24 hash-selected tasks; 12 workers; 600s limit. Audit every newly fitting task (8, below the preregistered cap of 16) at core depth 3. No symmetry, repair or test-label-driven search/selection.
Result: objects fit **17/400**, solve **16/400**, and add **8 fitting / 7 correct tasks** beyond core depth 2. Grid-first fallback and validation gate both solve **60/400 (15.00%)**, versus grid **53/400 (13.25%)**; union oracle **61/400** versus **54/400**. Grid accuracy here is exhaustive enumeration, not the complete production solver. All seven gains also lack a correct core-depth-3 program, and are unsolved in the retained complete-solver baseline. Full comparison/validation takes ~3.8s, ~22.6s including audit, ~116 MiB peak RSS. Nine semantic/isolation tests pass; known core counts reproduced; repeated runs' saved pools agree byte-for-byte.
Representation finding: reserved-answer probability favours objects on **10 tasks**; objects solve **9/10** of their test answers, grid **2/10**. Both families fit discovery data on **11 tasks**; among these, probability favours objects on **3**, grid on **2**, ties on **6**; object/core test correctness on the three object-preferred tasks is **3/2**. A normalized grid length prior changes no object-preference decisions. This is limited predictive evidence for a useful representation, not a calibrated classifier of tasks as intrinsically "about objects". The gate ties simple fit-based fallback at 60, which is also the ceiling for choosing between the two proposed programs: there was no opportunity to improve by family selection. An additional entropy-selection benefit is not established.
Examples: `88a62173`, extract same-colour 8-connected objects, select the unique occupancy shape and crop it; 20 fitting ASTs agree on the correct test answer, while four named segmentation interpretations survive (2 bits). `a87f7484` narrows eight interpretations to one. Counterexample `67385a82`: reserved-answer probability 1, full training fit, and unanimous test prediction, but wrong. Low entropy does not establish truth. Other gains: `42a50994`, `25d8a9c8`, `aedd82e4`, `9565186b`, `23b5c85d`.
Decision: candidate criterion met by seven verified gains beyond audited depth 3; retain the object AST for later integration and abstraction experiments. Keep the production solver unchanged. Remaining integration and interpretation limitations are in the protocol. No public evaluation tasks used and no claim of an all-depth expressivity separation.
Code/evidence: [protocol and candidate code](003-objects/README.md), [illustrated example](evidence/003-objects/object-example.png); direct [full report](evidence/003-objects/full/report.md) and [pilot report](evidence/003-objects/pilot/report.md), original manifests/logs/selections. Frozen pools: ignored `out/experiments/003-objects/20260918T060901.136402Z-full/pools/`, hashes retained in the manifest. The report refinement adds shared-fit diagnostics and suppresses negative-zero display; grammar/search unchanged.

### 004-competition — Can evidence or entropy select among viable interpretations?
Status: closed — insufficient improvement opportunity; no selector integration.
Baseline: `45afda6`; implementation `af956b0`; unchanged stable core hash `e76a7031af456aeba4348a32b08e32017f44641eb17256e1b01e09a5985a7f5c`. 2026-09-18. Shared 003 grammar/API, nine families (grid plus eight object interpretations); no new primitives.
Comparison: 400 public training tasks; full-training and deliberately limited two-pair conditions. Discovery fits are conditioned on an additional example; vocabulary frozen before its output is revealed. Fixed order versus predictive evidence versus minimum answer entropy, with the SAME first surviving program within each family. Test and unused-training outputs score only. Competitive cohort uses prediction disagreement, not correctness. Twelve workers; pilot 0.68s, full 2.80s (~19 MiB peak RSS), both conditions included. Six new tests and all nine 003 checks pass; shared API preserves all 48 old pilot pools; pilot/full diagnostics agree.
Opportunity/result: **full data:** 63 tasks have a surviving family, 16 have multiple families, just **2 disagree**. Fixed/evidence/min-entropy all solve **60/400**; family-choice ceiling **60**, so **zero recoverable errors**, with two correct baselines vulnerable to switching. **Two-pair:** 69 have surviving families, 17 multiple, **4 disagree**. Fixed **59/400**, evidence **60/400** (+1 win, no losses), min-entropy **59/400**. Family-choice ceiling **61**, so **two genuine improvement opportunities**, evidence recovers one, entropy neither. Among the four competing tasks: 2/4, 3/4, 2/4. Full-program ceilings are 61/full and 64/two-pair, requiring within-family program changes and not attainable merely by selecting families. Independent ceiling recomputation from saved proposals agrees.
Interpretation: preregistered minimum of five recoverable errors was not met in either condition. No broad ranking of selectors or rejection of entropy is justified. There is one descriptive predictive-evidence success: `23b5c85d`, object probability **7/16** versus grid **2/9** on the second example selects correct object cropping; both families' test-answer entropy is zero, so confidence cannot distinguish them. On `88a62173`, the first two examples give every object interpretation equal evidence probability **5/6** and zero answer entropy; four-neighbour interpretations predict undefined, eight-neighbour ones predict correctly. Fixed tie order chooses the wrong interpretation. The third training example eliminates the grid and all four-neighbour families, leaving four correct eight-neighbour aliases. This miss exposes undefinedness/tie handling and insufficient evidence, not proof that object abstraction or entropy is ineffective. Grid length-prior sensitivity changes no evidence choices.
Decision: close this bounded selector study without integration. Retain 003 as the object-language candidate. Future selector comparisons must measure attainable improvement first and handle undefined predictions explicitly; simple certainty is not evidence of correctness. Two-pair scores intentionally withhold available training examples and are not full-information production results. No public evaluation tasks used.
Code/evidence: completed 004 code deleted; reproducible implementation at `af956b0`. Retained [protocol](evidence/004-competition/protocol.md), direct [full report](evidence/004-competition/full/report.md) and [pilot report](evidence/004-competition/pilot/report.md), manifests, logs, selections and compact family/proposal JSONL. Shared object API and common run harness remain with 003; no duplicated solver.

### 005-relations — Relational object expressivity and informative evidence
Status: closed — no language integration; controlled mechanism verified.
Baseline: `df33dbf`; unchanged core hash `e76a7031af456aeba4348a32b08e32017f44641eb17256e1b01e09a5985a7f5c`. Run implementation `174357f`; supplementary end-to-end check `727728c`; 2026-09-18. Reused 003 extraction/selectors.
Comparison: eight segmentations, unique source/reference selectors, reference-colour transfer or adjacent move/copy, original canvas. Full 400 public training tasks against grid depth 2 + 003; 12 workers; pilot 0.94s, full 2.60s (~20 MiB peak RSS). Separately, 32 scene seeds × two balanced latent rules = 64 constructed cases, with a fixed two-hypothesis prior and a choice of four additional examples. One example distinguishes object-relative colour transfer from constant grid recolouring; three do not. Query selection never sees their answers or the latent rule.
Real-task result: **0/400 relational training fits**, hence no added correctness or depth-3 audit eligibility, after 6,617,592 candidate AST checks. Control/fallback remain **63 fitting, 60 correct, 61 oracle-correct** tasks. Nine checks pass, including recovering the intended relational AST end-to-end from independent synthetic teacher examples (with/without a distractor), so the zero-fit result is not explained by an inert enumerator. This rejects this narrow grammar as a useful addition on this corpus, not relational abstraction generally.
Controlled result: no extra/uninformative evidence **32/64 correct**, posterior entropy **1 bit**; first/random query **40/64** (random is exact expectation), mean entropy **0.75 bits**; expected-information-gain query **64/64**, entropy **0 bits**, matching the informative-query oracle. First/random identifies 16/64 rules; IG identifies all 64. Teacher artifacts independently verify initial equivalence, test disagreement, balanced informative-query positions and label-blind query choices.
Interpretation: these controlled outcomes are expected by construction, not new evidence of general ARC effectiveness or automatic representation discovery. They demonstrate where entropy is useful: selecting evidence that distinguishes plausible explanations. Individual deterministic models both have zero answer entropy. Additional labelled examples are supplied by the constructed teacher; ordinary ARC does not provide this oracle.
Decision: retire the unsuccessful relational extension and completed mechanism-check code. Keep 003 as the language candidate. A next language extension should first be grounded in a small training-task expressivity audit with explicit intended object programs, rather than another speculative operator sweep. No public evaluation data or production changes.
Code/evidence: runnable sources preserved at `727728c`; live 005 directory removed. Retained [protocol](evidence/005-relations/protocol.md), direct [full report](evidence/005-relations/full/report.md) and [pilot report](evidence/005-relations/pilot/report.md), manifests, logs, selections and one [controlled-case artifact](evidence/005-relations/full/controlled-cases.jsonl) (pilot identical). Raw empty fit pools remain reproducible and ignored.

### 006-repair-audit — What mechanisms repair training-perfect ARC programs?
Status: closed — retrospective catalogue complete; selected mechanism tested in 007. Catalogue and repair witnesses retained as reusable inputs for the ongoing repair research.
Baseline: external solver corpus `cristianoc/arc-agi-2-abstraction-dataset@ddf6a3e`; official ARC-AGI-2 data `f3283f7`; 2026-09-19. SymArc branch baseline `6e93e52`, core hash `e76a7031af456aeba4348a32b08e32017f44641eb17256e1b01e09a5985a7f5c` (inherited unchanged from 005; no SymArc execution or comparison here).
Comparison: census of 120 external Python solvers; twelve selected failure analyses, ten executable repairs. This initial audit preceded registration and inspected public evaluation test outputs. It is retrospective development evidence, not a preregistered or blind synthesis evaluation. Serial functional checks, no timing claim; the 12-worker SymArc benchmark policy is not being compared.
Result: originals fit all training pairs on 116/120 tasks; 27/120 pass every test, 38/167 test grids correct. Ten selected repairs preserve 25/25 training pairs and improve their supplied tests from 0/14 to 14/14. All 390 colour-permutation and 13 reflection/transpose checks pass. Mechanisms include role binding, relative coordinates, input legends, global aggregation, rank, path traversal, templates and instruction interpretation. No result shows raw AST anti-unification alone discovers a successful solver. Partial `0934a4d8` symmetry repair gets 19/27 cells; eight have no observed in-grid orbit witness. `5dbc8537` assembly diagnosis remains unverified.
Decision: use explicit witnesses to ground the next bounded expressivity/discovery study, following 005. No language or policy integration; these hand repairs do not establish gains over SymArc or automatic discovery. Path traversal was selected and preregistered in 007: it expresses the known repair, but does not add public-training coverage or resolve family selection. Retain this catalogue and its executable witnesses to ground subsequent mechanism studies; this is the concrete exception to deleting closed experiment code. Do not use these inspected test answers as an untouched holdout.

### 007-path-order — Does preserving path order add useful expressivity?
Status: closed — no language integration; known-witness representation/selection gap confirmed.
Baseline: `3553c00`; preregistration `8ed404a`; runnable implementation `cd7e58b`; unchanged core hash `e76a7031af456aeba4348a32b08e32017f44641eb17256e1b01e09a5985a7f5c`; 2026-09-19.
Comparison: finite segment/select/simple-path unfolding versus matched one-run-per-colour histogram and grid d2 + 003 objects. Training-only fitting with fixed first-fit selection; known 006 witness development-only, then 400 previously used public training tasks; 24 hash-selected pilot, 12 workers. Pilot 0.467s, full 3.079s (~9 MiB peak RSS). No grammar tuning. All five targeted tests pass; stable reference counts reproduced.
Public-training result: **0/400 path fits**, after 575,520 histogram/path AST candidates and 576,192 training-example checks. Control, path fallback and path-first stay **63 fitting / 60 correct / 61 oracle-correct**. Sole histogram fit `d631b094` already solved by core. No d3-audit eligibility. Post-run output-shape check: only 12/400 tasks can meet the one-dimensional renderer restriction; this is a narrow language/corpus mismatch, not evidence against path reasoning generally.
Known-witness result: `7b5033c1` has **20 histogram fits and 20 path fits**, two distinct query predictions per family. First path predicts correctly; no histogram fit does. Control/path fallback still selects the wrong histogram; path-first succeeds on this already inspected example. Both families have the same 18:2 answer-frequency split, so uniform-fitting-AST answer entropy cannot distinguish them. A synthetic repeated-colour training example eliminates histogram fits while preserving path fits.
Decision: close under the preregistered no-new-coverage rule; no core/math changes. Preserving path order repairs a representational loss, but adding the correct representation does not choose it. This is neither automatic anti-unification nor an MDL evaluation. Before another grammar sweep, establish multiple applicable witnesses in the intended study corpus; separately investigate evidence distinguishing observationally equivalent wrong/right programs.
Code/evidence: completed runner removed; runnable at `cd7e58b`.
